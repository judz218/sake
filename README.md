# 酒の余白 — 日本酒記録 MVP

スマートフォン専用の日本酒ノート。記録はPC側のSQLiteに保存します。認証・クラウド同期・外部公開はありません。

## 起動（Windows / Node.js 22.13以上）

PowerShellでこのフォルダーを開きます。Node.js 22 LTSを推奨します。

```powershell
npm.cmd install
npm.cmd run dev
```

PCで http://localhost:5173 を開いてください。Vite（5173）とExpress（3001）が同時に起動します。終了は Ctrl+C。PowerShellの実行ポリシーに影響されないよう、READMEでは `npm.cmd` を使用しています。コマンドプロンプトでは `npm` も使えます。

```powershell
npm.cmd run build
npm.cmd test
```

ビルド後は `npm.cmd start` で http://localhost:3001 からも使用できます。このモードのExpressはPC内からのみ接続可能です。iPhoneで確認するときは `npm.cmd run dev` を使用してください。

## iPhoneからアクセス

1. PCとiPhoneを同じ信頼できるWi-Fiに接続します。
2. PCで `npm.cmd run dev` を起動します。
3. PowerShellで `ipconfig` を実行し、使用中の「Wireless LAN adapter Wi-Fi」のIPv4アドレスを確認します（例：192.168.1.20）。VPNなど別アダプターのアドレスは選ばないでください。
4. iPhoneのSafariで `http://192.168.1.20:5173` を開きます。Viteが表示するNetwork URLでも確認できます。
5. Windows Defenderファイアウォールの確認が出たら、信頼できる自宅ネットワークをプライベートに設定し、Node.jsのプライベートネットワーク接続だけを許可します。

接続できない場合は「Windows Defender ファイアウォール → 詳細設定 → 受信の規則」で、TCP 5173をプライベートプロファイル・ローカルサブネットに限定して許可してください。3001を開放する必要はありません。ゲストWi-Fiの端末分離、VPN、異なるサブネットも確認してください。ルーターのポート転送やインターネット公開は不要です。PCのIPが変わった場合はURLも変更します。

フロントエンドは相対 `/api` のみ使用します。ViteがExpressの `127.0.0.1:3001` に転送するので、PCとiPhoneは同じDBを使用します。

## 使い方

- 「＋ 記録」から既存銘柄を選ぶか新しい銘柄名を入力し、2ステップで保存します。前のステップに戻っても入力は残ります。下書きはその端末・タブのsessionStorageに保持し、保存成功時に破棄します。
- スライダー未操作はnull（未評価）。中間の50は「中間の50に評価」で明示的に選択できます。星も任意です。
- マップの円は1件の飲酒記録。タップで詳細、ドラッグ終了で保存。座標は0〜100に制限し、保存失敗時は元へ戻します。重なった記録はマップ下の一覧から選択できます。片方でも未評価なら履歴のみ表示します。
- 詳細から飲酒記録の編集・削除、日本酒情報と公式情報の編集、同じ銘柄の記録を閲覧できます。銘柄の削除は「履歴 → 登録済みの日本酒を管理」から。記録が残る銘柄の削除は拒否します。
- 公式座標は根拠の入力が必要です。日本酒度や酸度から生成しません。比較モードでは円＝自分、四角＝公式、点線＝対応関係。公式情報は正解として扱いません。
- 分析では件数、星の分布、4象限、未評価を除く平均、高評価一覧、特定名称・産地の回数を確認できます。
- 初期DBは空です。各主要画面下の「サンプルデータ」から10銘柄・11記録を任意投入できます。すべて架空です。「サンプルのみ削除」は実記録を削除せず、実記録が参照するサンプル銘柄も残します。編集したサンプル記録も引き続きサンプル扱いです。

## 構成・保存

```text
src/
  main.tsx       共通画面・履歴・詳細
  Form.tsx       2ステップ記録 / 日本酒編集
  Map.tsx        D3マップ / ドラッグ / 公式比較
  Analysis.tsx   基本集計
  api.ts         HTTP通信
  types.ts       共通データ型
  style.css      スマートフォン専用UI / Tailwind
server/
  index.ts       API起動
  app.ts         REST API / トランザクション / サンプル
  validation.ts  入力値検証
  db.ts          SQLite初期化 / マイグレーション
  api.test.ts    API統合テスト
data/sake.sqlite 永続DB（自動作成・Git対象外）
```

React・TypeScript・Vite・D3・Tailwind CSS・Expressを使用。SQLiteはNode.js標準の `node:sqlite`（Node 22では実験的警告が出る場合があります）。開発補助はtsx、concurrently。外部サービス・APIキーは不要です。

商品はsakes、飲酒体験はrecordsに分離。特定名称とその他分類、公式座標と主観座標も別フィールドです。DBは外部キー、WAL、トランザクションを使用し、再起動で初期化・削除しません。バックアップはサーバー停止後に `data` フォルダーごとコピーしてください。保存先は環境変数 `DB_PATH` で変更できます。

DBのスキーマバージョンはmigrationsテーブルで管理します。今後の変更では番号付きの移行を追加してください。公式情報の自動取得は将来server側の独立サービスとして追加できます。

API：`GET /api/data`、`POST /api/entries`（銘柄＋記録の原子的保存）、`POST /api/sakes`、`PUT/DELETE /api/sakes/:id`、`POST /api/records`、`PUT/DELETE /api/records/:id`、`POST/DELETE /api/samples`。成功は200/201、入力不正400、対象なし404、参照中の削除409、予期しない失敗500です。

## 検証と制限

`npm.cmd test` はメモリ内SQLiteでAPIをテストし、実DBには触れません。入力検証、null、座標保存、原子的保存のロールバック、CRUD、参照整合性、サンプル削除時の実記録保護を検証します。別の一時DBでは、書き込みプロセスの終了後に別プロセスでDBを開き直し、記録が保持されることも検証します。ビルドで全TypeScriptを型チェックします。

実装時の確認結果：API統合・プロセス再起動による永続化の2テストが成功。TypeScript型チェック・Vite本番ビルドが成功。開発サーバーの `/` とVite経由の `/api/data` はHTTP 200を確認しました。実機Safariの操作・見た目は未検証です。

iPhone実機のSafariで、セーフエリア、スライダー、マップのタップ/ドラッグ、画面遷移、再起動後の記録保持を確認してください。実機のWi-Fi・ファイアウォール接続とタッチ挙動は開発PCのみでは保証できません。

同時利用時は最後の保存が優先されます。オフライン保存・競合検出はありません。AI取得、認証、同期、写真、エクスポートは今回の対象外です。認証のないローカル用途のため、信頼できるLANだけで使用してください。
