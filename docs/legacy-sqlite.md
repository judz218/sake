# 酒の余白 — 日本酒記録 MVP

スマートフォン専用の日本酒ノート。記録はPC側のSQLiteに保存します。認証・クラウド同期・外部公開はありません。

## 通常モードとデモモード

通常モード：`npm.cmd run dev` → http://localhost:5173 、DBは `data/sake.sqlite`。

40件のデモを試す場合：

```powershell
npm.cmd run dev:demo
```

初回は30銘柄・40記録を専用DB `data/sake-demo.sqlite` に取り込み、http://localhost:5174 で起動します。iPhoneは同じWi-Fiから `http://<PCのIPv4アドレス>:5174` へ接続します。下記のファイアウォール手順では5173を5174に読み替えてください。APIも通常3001・デモ3002に分かれているため同時起動できます。使用中のポートから別ポートへ自動移動しません。

デモ画面には「デモ · すべて架空」と表示します。銘柄・酒蔵・説明・公式座標・飲酒体験はすべて創作で、公式比較も架空データ同士の比較です。登録・編集・削除を自由に試せます。再起動しても変更内容は残ります。

DBの初期化だけを行う場合、試用内容を破棄して元の40件に戻す場合：

```powershell
npm.cmd run demo:init
npm.cmd run demo:reset
```

再生成する前にデモサーバーを Ctrl+C で停止してください。`demo:reset` はデモ内の追加・編集も破棄します。通常DBは更新・削除しません。デモコマンドは `DB_PATH` を無視して専用パスを使います。`demo:init` と `dev:demo` は取込履歴を確認するため重複投入せず、削除した記録も勝手に復元しません。JSONを変更した際は `demo:reset` で反映します。

原本 `data/sake_demo_40.json` は変更せず、同じ内容を `demo/sake_demo_40.json` に配置してGit管理しています。取込履歴テーブル `demo_imports` はデモDBだけに作成します。

項目対応：`specialDesignation → designation`、`otherClassifications → classifications`（「・」区切り）、`officialSourceUrl → sourceUrl`、`sakeMeterValue → nihonshudo`、`officialSweetDry/officialLightRich → officialDryness/officialRichness`、`drankAt → date`、`sweetDry/lightRich → dryness/richness`。文字列の銘柄IDを数値IDへ対応付け、nullは未評価のまま保持します。香りは `none/light → 穏やか`、`strong → 華やか・強い`、`unknown → 未評価` に変換。公式座標の根拠には架空情報の注意書きと元の取得方法を保存します。

デモ導入時の検証結果：既存テストを含む4テスト、型チェック・ビルドが成功。実DBで初回30銘柄・40記録、再実行で追加なしを確認。非表示Edgeでマップ40点、公式比較32組（24銘柄）、履歴40件、分析40記録・30銘柄、詳細・新規フォームへの遷移を確認しました。375/390/430pxで横スクロールなし。iPhone Safari実機のタッチ操作は未検証です。

## 起動（Windows / Node.js 22.13以上）

PowerShellでこのフォルダーを開きます。Node.js 22 LTSを推奨します。

```powershell
npm.cmd install
npm.cmd run dev
```

PCで http://localhost:5173 を開いてください。Vite（5173）とExpress（3001）が同時に起動します。終了は Ctrl+C。PowerShellの実行ポリシーに影響されないよう、READMEでは `npm.cmd` を使用しています。コマンドプロンプトでは `npm` も使えます。

```powershell
npm.cmd run build
npm.cmd test
```

ビルド後は `npm.cmd start` で http://localhost:3001 からも使用できます。このモードのExpressはPC内からのみ接続可能です。iPhoneで確認するときは `npm.cmd run dev` を使用してください。

## iPhoneからアクセス

1. PCとiPhoneを同じ信頼できるWi-Fiに接続します。
2. PCで `npm.cmd run dev` を起動します。
3. PowerShellで `ipconfig` を実行し、使用中の「Wireless LAN adapter Wi-Fi」のIPv4アドレスを確認します（例：192.168.1.20）。VPNなど別アダプターのアドレスは選ばないでください。
4. iPhoneのSafariで `http://192.168.1.20:5173` を開きます。Viteが表示するNetwork URLでも確認できます。
5. Windows Defenderファイアウォールの確認が出たら、信頼できる自宅ネットワークをプライベートに設定し、Node.jsのプライベートネットワーク接続だけを許可します。

接続できない場合は「Windows Defender ファイアウォール → 詳細設定 → 受信の規則」で、TCP 5173をプライベートプロファイル・ローカルサブネットに限定して許可してください。3001を開放する必要はありません。ゲストWi-Fiの端末分離、VPN、異なるサブネットも確認してください。ルーターのポート転送やインターネット公開は不要です。PCのIPが変わった場合はURLも変更します。

フロントエンドは相対 `/api` のみ使用します。ViteがExpressの `127.0.0.1:3001` に転送するので、PCとiPhoneは同じDBを使用します。

## 使い方

- 「＋ 記録」から既存銘柄を選ぶか新しい銘柄名を入力し、2ステップで保存します。前のステップに戻っても入力は残ります。下書きはその端末・タブのsessionStorageに保持し、保存成功時に破棄します。
- スライダー未操作はnull（未評価）。中間の50は「中間の50に評価」で明示的に選択できます。星も任意です。
- マップの円は1件の飲酒記録。通常は閲覧専用で、タップすると詳細を表示します。「自分の評価」でカード内右上の「✎ 編集」を押した場合だけドラッグでき、タップは編集対象の選択になります。座標は0〜100、数値はドラッグ中も更新します。6px未満の移動や、最後に元の座標へ戻った場合は保存しません。変更はドラッグ終了時に自動保存し、失敗時は位置と数値を元へ戻して通知します。「✓ 完了」は保存ボタンではなく閲覧へ戻る操作です。保存中はモード切り替えと次のドラッグを止めます。他の表示タブへ移ると編集は終了し、再読み込みでも通常モードから始まります。公式比較・好みの傾向は常に閲覧専用です。重なった記録はマップ下の一覧から選択できます。片方でも未評価なら履歴のみ表示します。
- 詳細から飲酒記録の編集・削除、日本酒情報と公式情報の編集、同じ銘柄の記録を閲覧できます。銘柄の削除は「履歴 → 登録済みの日本酒を管理」から。記録が残る銘柄の削除は拒否します。
- 公式座標は根拠の入力が必要です。日本酒度や酸度から生成しません。比較モードは銘柄・飲酒日を選ぶ差分チャートで、円＝自分、四角＝登録された公式情報です。甘辛・濃淡を固定0〜100のスケールで比較し、差が10以下を暫定的に「近い評価」とします。片軸のみ登録されている場合はその軸だけ比較します。公式情報は正解として扱いません。
- 分析では件数、星の分布、4象限、未評価を除く平均、高評価一覧、特定名称・産地の回数を確認できます。
- 初期DBは空です。各主要画面下の「サンプルデータ」から10銘柄・11記録を任意投入できます。すべて架空です。「サンプルのみ削除」は実記録を削除せず、実記録が参照するサンプル銘柄も残します。編集したサンプル記録も引き続きサンプル扱いです。

## 構成・保存

```text
src/
  main.tsx       共通画面・履歴・詳細
  Form.tsx       2ステップ記録 / 日本酒編集
  Map.tsx        可視化タブの切り替え
  PersonalTasteMap.tsx       D3散布図 / 編集モード / ドラッグ
  OfficialComparisonChart.tsx 銘柄・飲酒日別の差分チャート
  PreferenceChart.tsx        4領域別の平均お気に入り度
  tasteAnalysis.ts           可視化用の集計・差分判定
  Analysis.tsx   基本集計
  api.ts         HTTP通信
  types.ts       共通データ型
  style.css      スマートフォン専用UI / Tailwind
server/
  index.ts       API起動
  app.ts         REST API / トランザクション / サンプル
  validation.ts  入力値検証
  db.ts          SQLite初期化 / マイグレーション
  api.test.ts    API統合テスト
data/sake.sqlite 永続DB（自動作成・Git対象外）
```

React・TypeScript・Vite・D3・Tailwind CSS・Expressを使用。SQLiteはNode.js標準の `node:sqlite`（Node 22では実験的警告が出る場合があります）。開発補助はtsx、concurrently。外部サービス・APIキーは不要です。

商品はsakes、飲酒体験はrecordsに分離。特定名称とその他分類、公式座標と主観座標も別フィールドです。DBは外部キー、WAL、トランザクションを使用し、再起動で初期化・削除しません。バックアップはサーバー停止後に `data` フォルダーごとコピーしてください。保存先は環境変数 `DB_PATH` で変更できます。

DBのスキーマバージョンはmigrationsテーブルで管理します。今後の変更では番号付きの移行を追加してください。公式情報の自動取得は将来server側の独立サービスとして追加できます。

API：`GET /api/data`、`POST /api/entries`（銘柄＋記録の原子的保存）、`POST /api/sakes`、`PUT/DELETE /api/sakes/:id`、`POST /api/records`、`PUT/DELETE /api/records/:id`、`POST/DELETE /api/samples`。成功は200/201、入力不正400、対象なし404、参照中の削除409、予期しない失敗500です。

## 検証と制限

ホームの可視化は3種類に分かれます。「自分の評価」は従来の散布図と編集モード、「公式情報と比較」は銘柄と飲酒記録を選ぶ甘辛・濃淡の差分チャート、「好みの傾向」は4領域の平均星評価を固定1〜5の横軸で示す棒グラフです。公式の公表値・推定値の表示は入力された根拠の記述をもとにし、アプリで検証・推定は行いません。架空データは明示します。

好みの集計は甘辛・濃淡・星がすべて評価済みの記録のみ使用し、同じ銘柄の再飲酒も別々に数えます。甘辛50以上は辛口側、濃淡50以上は濃醇側。平均は小数第1位、0件は「記録なし」と表示します。1〜5の棒の起点は1で、平均1にも小さな目印を表示します。少ない記録・領域間の件数の偏り・平均の差が小さい場合は好みを断定しません。分類も文章の判定基準もアプリ内の便宜的なもので、科学的な判断ではありません。

新しい可視化の確認：`npm.cmd test` で9テストが成功。`npm.cmd run build` の型チェック・ビルドが成功。`npm.cmd run test:map` で散布図の編集、差分チャートの銘柄・記録切り替え、出典リンク、片軸だけの公式情報、4領域の平均・件数、3モードの空状態、375/390/430pxの表示を検証しています。テストには一時SQLiteを使用し、実際の通常用・デモ用DBは変更しません。

味覚マップの編集操作は、ビルド後に `npm.cmd run test:map` でブラウザ検証できます。WindowsのEdgeを非表示・独立した一時プロファイルで起動し、メモリ内SQLiteに架空データを投入します。通常DB・デモDBには接続しません。Edgeが標準位置にない場合は `EDGE_PATH` に実行ファイルを指定してください。テスト後はブラウザ・一時API・一時プロファイルを終了／削除します。

検証済み：閲覧時の移動禁止と詳細表示、編集対象選択、6pxのしきい値、リアルタイム座標、終了時の1回保存、保存中の操作制御、画面再読み込み後の保持、失敗時の位置・数値の復元、表示タブ変更時の編集解除、公式比較・傾向の編集禁止、通常時のタッチスクロールと編集時のタッチドラッグ、元の位置へ戻した場合の保存省略、分析と375/390/430pxのレイアウト。iPhone Safari実機の確認は別途必要です。

`npm.cmd test` はメモリ内SQLiteでAPIをテストし、実DBには触れません。入力検証、null、座標保存、原子的保存のロールバック、CRUD、参照整合性、サンプル削除時の実記録保護を検証します。別の一時DBでは、書き込みプロセスの終了後に別プロセスでDBを開き直し、記録が保持されることも検証します。ビルドで全TypeScriptを型チェックします。

実装時の確認結果：API・永続化・デモ・可視化集計/表示の9テストが成功。TypeScript型チェック・Vite本番ビルドが成功。開発サーバーの `/` とVite経由の `/api/data` はHTTP 200を確認しました。実機Safariの操作・見た目は未検証です。

iPhone実機のSafariで、セーフエリア、スライダー、マップのタップ/ドラッグ、画面遷移、再起動後の記録保持を確認してください。実機のWi-Fi・ファイアウォール接続とタッチ挙動は開発PCのみでは保証できません。

同時利用時は最後の保存が優先されます。オフライン保存・競合検出はありません。AI取得、認証、同期、写真、エクスポートは今回の対象外です。認証のないローカル用途のため、信頼できるLANだけで使用してください。

## デモデータ概要

### 対象ユーザー

日本酒が好きで、これから日本酒について詳しくなりたい人を対象とする。

日本酒を飲んだ経験を記録し、自分が感じた味と公式情報を比較することで、味覚の特徴や好みの傾向を発見することを目指す。

### デモユーザーの設定

日本酒を飲み始めて約1年の架空のユーザーを想定する。

当初は淡麗辛口の日本酒を好むと考えていたが、さまざまな日本酒を飲み比べるうちに、実際には濃醇甘口の日本酒を高く評価する傾向が見えてきた、という設定である。

### デモデータの目的

以下の機能を確認・紹介するために作成した。

- **味覚マップ**：飲んだ日本酒を甘辛・濃淡の2軸上に配置し、味の違いを視覚的に比較する。
- **公式情報との比較**：自分が感じた味と公式の味覚評価の違いを確認する。
- **好みの分析**：星評価と味覚座標の関係から、好みの傾向を発見する。
- **飲酒履歴**：過去の記録を振り返り、同じ日本酒を飲んだ際の印象の違いを確認する。

### デモデータの内容

| 項目           | 内容                                                           |
| -------------- | -------------------------------------------------------------- |
| 日本酒         | 30銘柄                                                         |
| 飲酒記録       | 40件                                                           |
| 記録期間       | 2025年12月〜2026年11月                                         |
| 再飲酒記録     | 10件（30銘柄に対する追加記録）                                 |
| 公式比較データ | 24銘柄                                                         |
| 味覚評価       | 甘辛・濃淡をそれぞれ0〜100で表現                               |
| お気に入り度   | 星1〜5                                                         |
| その他の情報   | 酒蔵、産地、特定名称、香り、特徴タグ、一言メモ、飲んだ場所など |

味覚座標は4象限に分布するように設定し、濃醇甘口の日本酒に高評価が集まる傾向を持たせている。

また、一部の日本酒には公式の味覚座標と異なる主観評価を設定し、比較機能を確認できるようにしている。

### 注意事項

本デモデータに含まれる銘柄名、酒蔵名、公式説明、味覚評価、飲酒体験はすべて架空のものである。

実在する日本酒の情報や、実際のユーザーによる評価を示すものではない。
